# Доказательство и тесты

## Доказательство, а не «готово»
- Кто сделал правку, показывает вывод проверки (синтаксис и типы, вызывающие места) и рассуждение по сценариям.
- Доказательство результата — ручной прогон на тестовом стенде. Живые прогоны идут путём пользователя, через интерфейс продукта, а не скриптами к API.
- Находки прогона не теряй: вне этапов чини сразу (починка, стенд, повтор сценария), в этапах по `root-cause.md`.
- Стенда нет: проверяй локальным запуском и скажи об этом владельцу; что считать доказательством, запиши в `project.md`.
- После успешных проверок расширяй их только при новой правке или конкретном риске.

## Тесты
- Без прямой команды владельца проекта никто — ни агент, ни исполнитель, ни ревьюер, ни плагин — не пишет и не запускает тесты,
  реплеи, self-check-скрипты, assert-демо и проверочные прогоны, даже бесплатные.
- Исключение — тесты этапа по скиллу `stage-development`. Прямая команда владельца разрешает один запуск.
- Добавленные без команды тесты удаляются при приёмке.
- Старые тесты, фиксирующие прежнее поведение, могут покраснеть: попутно их не чини, в отчёте назови, какие, вероятно, покраснели.
- Без команды проверка — чтение diff, синтаксис и типы (команды — `project.md`). Проверка типов должна видеть зависимости проекта: без них она ложно даёт «чисто». Один раз проверь её на заведомо ошибочной временной строке и убери строку: это проверка инструмента, она разрешена без команды.
