# UI Design References - внешние образцы

Дизайн-система проекта (`DESIGN.md`, если есть, токены темы и существующие компоненты) **всегда важнее**. Внешнее - только там,
где решение ещё не принято, и как образец идеи, а не как копия кода или стиля целиком.

## Порядок

1. **Задача и место.** Какой экран/блок, что сейчас не так (скрин «до» - см. процесс `ui-reviewer`).
2. **Стиль (если нужен ориентир для нового блока/страницы или «выглядит плохо»).** Выбрать ОДИН
   образец под задачу, не смешивать несколько:
   - awesome-design-md (MIT, бренды: stripe, linear.app, vercel, notion, raycast, superhuman, runwayml,
     elevenlabs, lovable…): `bash tools/fetch-design-md.sh <brand>` (из папки этого скилла)
     → `docs/design-refs/<brand>.md`.
   - Refero Styles: https://styles.refero.design - поиск по стилю, страница стиля
     `refero.design/style/<id>` с DESIGN.md. Читать через WebFetch.
   - Из образца брать конкретику (сетка, иерархия, плотность, приёмы акцента), переводить на токены ПРОЕКТА.
3. **Компоненты.** Сначала посмотреть реализацию в зрелых системах, потом готовые блоки:
   - Component Gallery: `https://component.gallery/components/<name>` (modal, toast, tabs, card, pricing…) -
     как компонент сделан в зрелых дизайн-системах, доступность, варианты.
   - ui.watermelon (https://ui.watermelon.sh, бесплатные open-source блоки и анимации) и
     21st.dev (https://21st.dev/community/components) - образцы готовых блоков.
     Если стека образца (например, Tailwind) в проекте нет, код не вставлять, переносить структуру и идею на CSS/токены проекта.
     MCP 21st.dev (`npx @21st-dev/cli@latest init --client claude`) ставить только с «да»
     владельца проекта; перед каждым вызовом MCP сказать, что ищу (лимит).
   - aisdkagents (https://aisdkagents.com) - образцы UI чатов и ИИ-ассистентов: для поддержки, ассистента,
     стриминга ответов.
4. **Анимации.** Kinetics (https://kinetics.colorion.co, пружинные эффекты: CSS / React / промпт,
   видно stiffness/damping). Брать CSS-вариант, переводить на переменные проекта; всегда уважать
   `prefers-reduced-motion`; без анимаций ради анимаций.
5. **Макет до кода.** Показать макет (виджет или скрины ветки) владельцу проекта, код - после «да».
   Дальше - процесс `ui-reviewer`: тестовый стенд, скрины на ширинах из `project.md`, светлая и тёмная,
   проверка переполнения.

## Правила

- Не читается страница источника - остановиться и попросить владельца проекта вставить содержимое; ничего не
  подставлять по памяти.
- В отчёте всегда называть: какой внешний образец взят (ссылка) и что именно по нему изменено.
- Не ставить новые npm-зависимости ради компонента из каталога без «да» владельца проекта.
- Мелкая правка (цвет, отступ, текст) - без этого скилла, просто сделать.
