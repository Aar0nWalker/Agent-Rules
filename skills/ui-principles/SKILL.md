# Принципы интерфейса

Обязательный стандарт при проектировании и доработке экранов. Дизайн-система и решения владельца проекта важнее конкретных визуальных приёмов отсюда.

## Главное

1. **Интерфейс понятен любому человеку без инструкции.** Если нужно объяснять, значит, нужно упрощать.
2. **Никаких зависаний в тишине.** Любое долгое действие сразу блокирует кнопку, показывает индикатор и понятный текст.
3. **Статусы обновляются на лету**, без перезагрузки страницы.
4. **Бесплатное и платное строго разделены, цена видна до списания.** Обычное сохранение никогда не списывает деньги, платное действие называет цену на кнопке, случайно нажать его сложно.
5. **Простое действие под рукой, сложное глубже.** Простой вариант доступен прямо на экране, для сложного есть переход в расширенный режим.
6. **Любая ошибка даёт решение и кнопку действия**, а не тупик.
7. **Простой человеческий язык:** без внутренних терминов и полотен текста.
8. **Аккуратная форма:** ровное выравнивание по сетке, единый стиль, без лишних рамок.

## Частые ошибки и как правильно

| Ошибка | Как правильно |
| :--- | :--- |
| Много пустого места в модалке, кнопки далеко | Модалка компактная по содержимому, кнопки рядом с действием |
| Контейнеры в контейнерах | Убрать вложенные рамки: воздух, лёгкие подложки или список строк |
| Заголовки, которые повторяют очевидное | Убрать, содержимое говорит само за себя |
| Два скроллбара | Страница или модалка прокручивается одним потоком |
| Браузерные подсказки через `title` как единственный способ | Подсказка в стиле интерфейса, рядом с элементом |
| Меню раздвигает экран | Выпадающее меню поверх содержимого, переходы плавные |
| Главное действие не выделено | Заметная кнопка акцентного цвета, с ценой, если действие платное |
| Удаление выглядит как обычная кнопка | Необратимые действия красным и с подтверждением |
| Текст предлагает шаг, которого нет на экране | Кнопка для предложенного шага обязана быть рядом |
| После «назад» видны старые статусы | Состояние синхронизируется при навигации по истории браузера |
| Перевод меняет раскладку | Локализация меняет только тексты, раскладка и логика те же |
| Одна кнопка дублируется | Одно действие, одна кнопка на экране |

## Что считается браком

- Полотна текста в карточках: 2-3 строки и разворот на месте.
- Вложенные рамки и коробки внутри коробок.
- Тупиковые и пугающие системные ошибки: внутренние сбои не показывать, всегда есть кнопка решения.
- Сложное и дорогое действие, запущенное автоматически, без запроса пользователя.
- Невозможность отменить обработку или вернуться к исходному результату.
- Случайные платные нажатия: нельзя совмещать сохранение со списанием денег.
- Шрифтовой разнобой: шрифты и их роли только по дизайн-системе.
- Мерцающие лоадеры и несколько экранов загрузки подряд.

## По типам экранов

### Списки и карточки
- Прежнее содержимое не исчезает при повторной операции, пока она не завершится.
- Из развёрнутых блоков раскрывается только выбранный.
- Индикатор процесса показывает примерное время ожидания, если оно известно.
- У каждого элемента пачки есть своя отмена.
- Действие, зависящее от результата других, заблокировано, пока они идут.
- В списках лёгкие превью вместо тяжёлых вложений, быстрая подгрузка.

### Редактирование
- Ручная альтернатива рядом с основным автоматическим путём.
- Подсказки ненавязчивые: значок «?», пояснение по клику.
- Описания полей простым языком, без шаблонных фраз.

### Создание и входные данные
- Не пропускать дальше без обязательных данных.
- Если один способ ввода не сработал, рядом есть другой.
- Окно создания компактное, единым блоком. Второстепенные способы добавить данные спрятаны в кнопку.

### Модалки и ошибки
- Компактный корпус без пустот, кнопки рядом.
- При сбое понятный текст и кнопка «Понятно» либо варианты («Попробовать ещё раз»).
- То, что можно пропустить без потери результата, можно выключить с пояснением и включить обратно.
- Любое окно закрывается крестиком, кликом по фону и Esc.

### Мобильная версия
- Полноценный интерфейс под палец, а не урезанный десктоп.
- Основная ширина из `project.md` вылизывается: кнопки в ряд, подписи в строку. Самая узкая поддерживаемая - только
  «не ломается», пиксели не полируются.
- Всё нажимаемое не меньше 44 px. Больше двух действий на карточке: одна главная кнопка и «⋯», а не ряд мелких значков.
- На самой узкой поддерживаемой ширине нет прокрутки вбок, всё нажимается, слова не рвутся посреди.

## Сверка перед «готово»
- Из любого состояния есть путь назад или отмена без потерь.
- Одна и та же операция называется и выглядит одинаково на всех экранах.
- Обязательное пустое поле блокирует кнопку, а не падает ошибкой сервера.
- Уже выбранное и введённое видно на экране; то, что система знает, предзаполнено.
- На новом экране сначала главное действие, второстепенное - за раскрытием или следующим шагом.
- Тёмная тема - сразу вместе со светлой: не чистый чёрный и белый, тени и свечение проверяются на контраст к фону,
  картинки с белой подложкой адаптированы.

## Внешние образцы
Только там, где решение ещё не принято, и как образец идеи: один образец на задачу, конкретику (сетка, иерархия, плотность)
переводить на токены проекта, чужой код не вставлять. Дизайн-система проекта всегда важнее. Новые установки - с «да»
владельца. В отчёте - ссылка на образец и что по нему изменено.

## Процесс

1. **Постранично.** Одна страница до эталона, согласовать, затем следующая.
2. **Макет перед кодом для крупных изменений.** Крупная переделка: сначала «было / стало». Локальная правка: сразу делать и показывать скрины до и после.
3. **Глазами на тестовом стенде.** Правка интерфейса проверяется браузером под служебным аккаунтом на готовых данных, а не по
   коду. Жалоба на «пропавший» элемент - сначала самому снять скрин этой стадии, а не гадать.
4. **Размеры не трогать без просьбы.** Карточки, превью и панели сохраняют размер; нужна другая геометрия - менять контейнер,
   а не элемент.
5. **Сначала корень.** Найти причину дефекта и предложить решения.
6. **Прод - по правилу из `project.md`.**
7. **База знаний поддержки**, если она есть, обновляется вместе с видимым поведением.
