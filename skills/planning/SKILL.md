# Planning And Task Breakdown

Применять перед нетривиальной реализацией.

План — из пяти пунктов:

1. Цель.
2. **Сценарий приёмки** (для функций с пользовательским путём): 3–5 шагов «пользователь делает X → видит Y». Финальная проверка идёт по этим шагам, а не только по тестам — тесты автора кодируют понимание автора, сценарий ловит именно ошибку понимания.
3. Наименьший набор затронутых файлов и модулей.
4. Автоматическое масштабирование после просмотра затронутых файлов: 0–1 исполнитель, когда декомпозиция мало что даёт, 2–3 для независимых ограниченных линий, 4–5 только для крупной работы с чётко непересекающимся владением файлами.
5. Целевая проверка для каждой линии плюс итоговая узкая интеграционная проверка главной сессии; для изменённых UI-флоу сюда входит ручной проход сценария приёмки на тестовом стенде и снимки ключевых этапов.

У каждой делегированной линии должны быть точная область, результат, режим владения и проверка. Субагенты — только для ограниченного анализа или изолированных правок; итоговая интеграция остаётся за главной сессией. Сбой, вызванный текущим изменением, остаётся в той же задаче: исправь и повтори упавшую проверку до отчёта о завершении.
