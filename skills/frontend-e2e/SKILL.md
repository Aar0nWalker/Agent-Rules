# Frontend E2E (Playwright, замоканный бэкенд)

Применять после правок логики и поведения интерфейса. Чисто текстовым и косметическим правкам без изменения поведения хватает
проверки типов.

## Запуск

Каталог e2e и команды (весь mock-набор / один спек) - в `project.md`. Запускает только главная сессия, исполнители спеки пишут.

## Состояния, которых нет в готовых данных

Путь пользователя по изменённому флоу - скилл `frontend-ui-engineering`, «Визуальная проверка». Состояния, которых нет в готовых
данных служебного аккаунта, - спек с моками: за основу ближайший mocked-спек проекта; бэкенд замокан, платных вызовов нет.

## Охрана

- mocked-спеки - для регрессии и состояний, которых нет в готовых данных; сам путь пользователя проверяется на стенде;
- полные спеки на реальном бэкенде - только когда изменение зависит от реального контракта с бэкендом;
- исправил реальный баг фронтенда - регрессионный спек на его класс (`proof-and-tests.md`);
- мок обязан проверять то, что получает (assert на тело/параметры запроса): мок, принимающий что угодно, не проверяет ничего -
  «стыковый баг → стыковый тест», расширять мок ради зелёного запрещено.

## Ожидаемый результат

- mock-набор проходит без необработанных запросов к API;
- изменённый флоу покрыт спеком или в отчёте сказано, почему спек не нужен.
