# Frontend E2E (Playwright, замоканный бэкенд)

Запуск и написание спеков - только по прямой команде владельца проекта (один запуск) или как тесты этапа. Без команды скилл не применять.

## Запуск

Каталог e2e и команды (весь mock-набор / один спек) - в `project.md`.

## Проход по команде

1. Взять acceptance-сценарий из плана (3–5 шагов «делает X → видит Y»).
2. Пройти его в mock-e2e: за основу - ближайший mocked-спек проекта; бэкенд замокан, платных вызовов нет.
3. Снять `page.screenshot` каждой ключевой стадии в скретчпад сессии и назвать их в отчёте.
4. Расхождение с сценарием - чинить в той же задаче, не отчитываться «готово».

## Охрана

- предпочитать mocked-спеки;
- полные спеки на реальном бэкенде - только когда изменение зависит от реального контракта с бэкендом;
- мок обязан проверять то, что получает (assert на тело/параметры запроса): мок, принимающий что угодно, не проверяет ничего, расширять мок ради зелёного запрещено.

## Ожидаемый результат

- mock-набор проходит без необработанных запросов к API.
